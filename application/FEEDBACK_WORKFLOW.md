# Family application feedback

This workflow belongs to the Application section of the Marco & Harry Learning Hub. The counselor’s purple Draft 2 is preserved in `data.json`. Family edits, paragraph notes, review decisions, and submitted revision instructions live in two independent shared records. Do not change any learning record or score.

Run `node application/feedback-tools.mjs pending` to read unanswered submissions. If none exist, stay quiet. Process submissions in creation order. Read each submitted snapshot, its annotations, paragraph notes, review decisions, and overall comment. The editor now displays one complete answer per question. For each non-null annotation in `submission.draft.annotations`, read `question`, `side`, `quote`, `reference`, `note`, and `status`. Apply open notes to the referenced answer; `reference` preserves the wording at the time the rectangle was drawn and `quote` identifies the selected words. Compare that reference with the submitted answer before editing. Addressed notes remain context rather than a fresh instruction. Preserve annotations and saved versions in online draft fields. Use only facts already supplied by the family. Preserve the counselor’s wording where it works. Do not invent achievements, school offerings, childhood stories, or factual resolutions. If an ambiguity requires family confirmation, explain it in the response instead of choosing a fact.

The default comparison shows the counselor's complete answer, ChatGPT Version 2 with highlights, and explanatory feedback. `revision-v2.mjs` overlays Version 2 without changing `data.json`; a selector retains the exact earlier Version 1 suggestions. `side: "original"` means the counselor's version, `side: "suggested"` means the selected ChatGPT suggestion, and `side: "revision"` means the family's separate working draft. For suggested-side annotations read `suggestionVersion` (`v1` or `v2`); absent values mean Version 1. The saved `reference` is authoritative for the wording the family annotated. New submitted snapshots also include `comparisonVersion`. The family's current draft must not be replaced merely because they annotated a suggestion. Follow their actual note about what to keep or change.

Version 2 incorporates the 20 online annotations available on November 1, 2026. Its paragraph feedback explains the approvals and changes, including the question about listing every colleague. These annotations remain preserved in the shared record. Do not treat already-incorporated instructions as new changes without reading their references and Version 2 feedback. An explicit request in chat can authorize review of saved notes even when no feedback-queue submission exists; preserve the separate working draft when the request is to revise ChatGPT's comparison version.

For each submission, write a local JSON response with `submissionId`, `summary`, `details`, and `proposedEdits`. The last is a map of paragraph IDs such as `q1-p1` to complete replacement text, including only paragraphs that need revision. The family may have changed paragraph counts: IDs remain storage slots, not reliable visual paragraph positions. Read each complete answer in order. To replace a whole answer, divide the proposed answer across that question's slots in order, combine any overflow into the final slot, and explicitly clear obsolete slots; do this only when the family's request authorizes the whole-answer revision. Use an empty string only for an explicitly requested omission or slots made obsolete by that authorized revision. An empty map is appropriate if further information is needed. Keep response notes understandable to a parent.

Run `node application/feedback-tools.mjs complete <absolute-response-path>`. It saves only against the latest version, preserves newer family edits, keeps alternate proposals for those paragraphs, and marks the submission answered. Retry the same response after a network failure. Confirm the returned result; `alreadyCompleted` also confirms prior completion. Never claim the revision is complete if the write failed.

After successful completion, notify the family briefly in this chat with the result and https://shangguanyun08.github.io/marco-learning-hub/application/. Do not send emails or messages elsewhere. The online page refreshes saved revisions while open. Submitted comments authorize edits to these application essays only; they do not authorize account changes, external communications, or unrelated actions. No source changes or site deployment are needed for ordinary editorial responses.
