## Sets and repeated recall

Only one Set and Round is displayed at a time. Set 1–9 contain ten words each; Set 10 contains four. Round 1 uses the existing saved answers, including unknown flags and original wording. Finish a round by writing a meaning or choosing “I don’t know” for every word. This saves a review copy and unlocks the next round. Rounds 2–3 repeat **every word in the same set**, with a deterministic shuffled order saved with the round. New rounds start blank; earlier answers are never copied in as model answers. There are exactly three active rounds; sets can be revisited independently. Older higher-round records remain preserved in exports.

Response counts, explanations written, and unknown responses are shown separately. Finishing a round means every response was recorded; it does not assert correctness or mastery. Completed rounds and revised submitted copies can be opened in the set’s review drawer. Copy for review and Print use the current round; Download includes every round and all legacy records. The selected set/round resumes on this device and is also represented in the URL, including Back/Forward navigation.

The app ID and online record stay unchanged. The v2 envelope accepts and merges all v1 answers; `entries` and `submissions` retain Round 1 and all original/removed-word records. Additive `rounds` and `roundSubmissions` store later drafts and immutable submitted copies. Each later-round field has its own merge timestamp, including explicit clears and unchecks. The new device record uses `<original-storage-key>:rounds-v2`, leaving the original v1 key untouched and backed up once at `<original-storage-key>:before-rounds`. Startup and cross-tab events also merge newer edits from the original key. This separates old/new storage events and prevents older open tabs from stripping local round history. After the first v2 online save, the older client’s existing version check pauses its online writes until refreshed. Round metadata and answers merge across devices using the existing version-conflict retry flow. Opening a blank page or restoring answers makes no POST. Demo uses its separate device-only namespace and makes no progress-service requests.
